# Community plugin registry

How AniMathIO 2.2+ finds, verifies and installs community plugins
([AniMathIO#304](https://github.com/AniMathIO/AniMathIO/issues/304)). This page is the
contract between this repository and the editor.

```
community-plugins.json   hand-edited, reviewed by PR (id, name, author, repo, license, ...)
        |                        nothing here changes per plugin version
        v   scripts/registry.py index   (.github/workflows/index.yml)
community-index.json     generated: latest release, download URL, SHA-256, ABI per plugin
        ^
        |  GitHub releases (assets `<id>-<version>.amplugin` + `.sha256`)
        +- AniMathIO/plugins   tag `<id>@<version>`, made by release-plugin.yml
        +- <author>/<repo>     the author's own releases
```

The editor fetches **one static file**:

```
https://raw.githubusercontent.com/AniMathIO/plugins/main/community-index.json
```

and downloads plugins only from the `download_url` it contains. Both files have a JSON
Schema in [`schemas/`](../schemas) (`community-plugins.schema.json`, `community-index.schema.json`).

## `community-plugins.json` (the registry)

```json
{
  "$schema": "./schemas/community-plugins.schema.json",
  "schema_version": 1,
  "plugins": [
    {
      "id": "io.github.animathio.code-snippets",
      "name": "Code Snippets",
      "author": "AniMathIO",
      "description": "Syntax-highlighted code with type-on reveal and token morph animations",
      "repo": "AniMathIO/plugins",
      "path": "community/code-snippets",
      "license": "MIT AND OFL-1.1",
      "min_abi": "1.1.0"
    }
  ],
  "delisted": []
}
```

(An entry for a plugin in another repository also has `"repo_id": 123456789`.)

| Field | Rule |
| --- | --- |
| `id` | Reverse-domain, lowercase, at least three dot-separated labels, at most 100 characters. Unique. **Never `org.animathio.*`**: those ids are reserved for first-party plugins and the host refuses to load them from the user plugin folder. Windows device-name prefixes (`con`, `nul`, `com1`–`com9`, etc.) are refused, matching the host. Must equal `id` in the plugin's `plugin.toml`. |
| `name`, `author`, `description` | Display text (60 / 80 / 10-200 characters). Names are unique (case-insensitive). |
| `repo` | Public GitHub repository `owner/name` that carries the release assets. |
| `repo_id` | Numeric GitHub id of `repo` (`gh api repos/<owner>/<name> --jq .id`). Required outside AniMathIO/plugins. The index builder refuses releases if the configured name resolves to a different numeric id, including deletion and re-creation or reuse of an old name. Renames and transfers preserve the numeric id; this pin does not detect ownership changes or require their re-review. |
| `path` | Optional subdirectory of `repo` that holds the plugin (`plugin.toml`, `build.sh`). Required for plugins hosted here (`community/<name>`). A plugin with a `path` is a monorepo plugin: its release tags must be `<id>@<version>`. |
| `license` | SPDX expression, e.g. `MIT`, `Apache-2.0 OR MIT`, `MIT AND OFL-1.1`. Every identifier must be OSI-approved or an SIL OFL variant ([`schemas/osi-approved-licenses.txt`](../schemas/osi-approved-licenses.txt)). For plugins outside this repository, the licence GitHub detects in the repository must be one of the declared identifiers. |
| `min_abi` | The plugin ABI (`api_version` in `plugin.toml`) of the latest release. The index builder refuses a release whose manifest says otherwise, so raising the ABI is a one-line PR together with the release. |
| `delisted[]` | `{ "id", "reason", "date" }` for removed plugins. A delisted id can never be listed again. |

No version, URL or checksum lives here: they are resolved from releases.

## Releases

A release is a GitHub release in `repo` with exactly two assets:

| Asset | Content |
| --- | --- |
| `<id>-<version>.amplugin` | The plugin bundle (a zip with `plugin.toml` and `plugin.wasm` at its root). |
| `<id>-<version>.amplugin.sha256` | `<lowercase sha256>  <asset name>` (`sha256sum` format). |

* **Tag:** `<id>@<version>` for every plugin; additionally `v<version>` or `<version>` for a
  plugin that has no `path` (one plugin per repository). `<version>` is `MAJOR.MINOR.PATCH`.
* The bundle's `plugin.toml` must have the same `id`, the same `version` and `api_version == min_abi`.
* Draft and pre-release releases are ignored. The latest version is the highest
  `MAJOR.MINOR.PATCH` (numeric, so `1.10.0 > 1.9.0`) among the remaining releases.
* Releases are immutable: never replace an asset, publish a new version instead.
* Plugins hosted here are released by [`release-plugin.yml`](../.github/workflows/release-plugin.yml)
  when a `<id>@<version>` tag is pushed (see [RELEASING.md](../RELEASING.md)). Plugins in their
  own repository are released by their author (see CONTRIBUTING.md for a ready-made workflow
  recipe: `bash build.sh`, then upload the two assets).

## `community-index.json` (what the editor reads)

Generated by `scripts/registry.py index` from the registry and the releases: for each plugin it
downloads the latest release asset, recomputes its SHA-256, checks it against the `.sha256`
asset, opens the archive and checks `plugin.toml`. Never edit it by hand.

```json
{
  "$schema": "./schemas/community-index.schema.json",
  "schema_version": 1,
  "plugins": [
    {
      "id": "io.github.animathio.code-snippets",
      "name": "Code Snippets",
      "author": "AniMathIO",
      "description": "Syntax-highlighted code with type-on reveal and token morph animations",
      "license": "MIT AND OFL-1.1",
      "repo": "AniMathIO/plugins",
      "path": "community/code-snippets",
      "source_url": "https://github.com/AniMathIO/plugins/tree/HEAD/community/code-snippets",
      "kinds": ["clip-source"],
      "min_abi": "1.1.0",
      "version": "0.1.0",
      "download_url": "https://github.com/AniMathIO/plugins/releases/download/io.github.animathio.code-snippets@0.1.0/io.github.animathio.code-snippets-0.1.0.amplugin",
      "sha256": "bf7bb255cf4f5dc90f49749679197a1c8799193648082fd7946a2b540d33d725",
      "size": 795124,
      "released_at": "2026-11-17T01:00:00Z"
    }
  ],
  "delisted": [
    { "id": "com.example.removed", "reason": "Unmaintained", "date": "2026-11-20" }
  ]
}
```

(Example values; the real file is the source of truth.)

| Field | Meaning |
| --- | --- |
| `schema_version` | `1`. A client that sees another value must ignore the file and say it needs a newer AniMathIO. Unknown extra fields must be ignored (they are only added in a compatible way within version 1). |
| `plugins[]` | One entry per listed plugin **that has a verified release**, sorted by `id`. Only the latest release is described. |
| `id`, `name`, `author`, `description`, `license`, `repo`, `path?` | Copied from the registry. |
| `source_url` | Human-facing link to the source (open in a browser; never downloaded). |
| `kinds` | Plugin kinds from the release's `plugin.toml` (`clip-source`, `effect`, `audio-effect`, `animation-preset`, `importer`). |
| `min_abi` | `api_version` from the release's `plugin.toml`: the minimum host plugin ABI. Show it in Browse and apply the same compatibility rule the host applies when loading a bundle (reuse that code), instead of reimplementing it. |
| `version` | Latest version (`plugin.toml` `version`). Compare numerically per component with the installed version to offer updates. |
| `download_url` | HTTPS URL of the `.amplugin` asset on `github.com` (redirects to GitHub's CDN). Download only this, never anything derived from `repo`. |
| `sha256` | Lowercase hex SHA-256 of the file. **Reject the download if it differs.** |
| `size` | Bytes. Reject a download larger than this. |
| `released_at` | RFC 3339 UTC publication time of the release. |
| `delisted[]` | `{ id, reason, date }` removed plugins. If one is installed, show a notice with the reason; do not remove it silently. |

### Client rules

1. Fetch the index with a short timeout and no personal data (the update check's client).
   `ANIMATHIO_NO_UPDATE_CHECK=1` disables background fetches; an explicit Browse click is a
   user action. Honour `ETag` / `If-None-Match` (raw.githubusercontent.com caches for about
   five minutes). On failure, keep working with the plugins already installed.
2. Install = download `download_url`, check size and `sha256`, open the archive and confirm
   that `plugin.toml` has the index `id` and `version` and that `kinds`/`api_version` match,
   then write it atomically to the user plugin folder (suggested file name `<id>.amplugin`, so an
   update replaces it). The editor refuses `org.animathio.*` ids already.
3. Installed plugins start disabled; the user enables each one.
4. A project that references a plugin id that is not installed can offer "Install" when that
   id is in the index.

### Failure handling

The index is regenerated whenever a plugin is released here, whenever `community-plugins.json`
changes and every six hours (for plugins released from other repositories). If one plugin's
latest release cannot be verified (missing asset, checksum or manifest mismatch, deleted
release), that plugin is **left out** and the run reports a warning, the other plugins still
update. If GitHub itself is unreachable or rate limiting, the previous entries are kept.
Pull requests that touch the registry run the same resolution strictly.

## Trust model

* A listing is reviewed once, by pull request; **new versions of a listed external plugin are
  indexed automatically** (no PR per release), because the issue's design is that the user
  installs and updates each plugin explicitly. Nothing is installed or updated without the
  user's click, downloads are checked against the index SHA-256, and plugins run sandboxed.
* The registry pins the repository identity (`repo_id`) and the index builder verifies the
  release asset against its `.sha256`, the archive manifest against the registry id and `min_abi`,
  and refuses `org.animathio.*`. A maintainer can delist at any time; to stop one version only,
  delete that release (the previous release becomes latest).
* Submission CI runs a plugin's own `build.sh` from its repository **only for pull requests that
  add or change that entry**, in a step that gets no token or secrets (the workflow has
  read-only permissions; GitHub withholds secrets from fork PRs). It checks that the source builds and
  produces the same id, version and ABI as the release; it does not require byte-identical
  output (zip timestamps and toolchains differ), so the release asset, not the source, is what
  the editor installs and what the smoke test renders. Pushes to `main` and manual runs download and
  render released assets but never build third-party source.

## Submitting, releasing, delisting

* Submission: [CONTRIBUTING.md](../CONTRIBUTING.md). CI is
  [`registry.yml`](../.github/workflows/registry.yml): schema, unique and unreserved ids, public
  repository, OSI/OFL licence, README table in sync, a strict resolution of the release, then
  build (`wasm32-wasip2`) and load/render with the released AniMathIO CLI
  ([`scripts/registry_smoke.py`](../scripts/registry_smoke.py)). A source plugin must draw
  something with its default parameters; other kinds are checked for loading only.
* Releasing plugins hosted here: [RELEASING.md](../RELEASING.md).
* Delisting: a maintainer moves the entry to `delisted` with a reason. The next index run drops it
  from `plugins` and lists it under `delisted`.

## Scripts

All are Python 3.11+ (`scripts/requirements.txt`: `jsonschema`, `Pillow`).

| Command | Does |
| --- | --- |
| `python3 scripts/registry.py validate [--offline]` | Static checks (the submission CI). |
| `python3 scripts/registry.py table --write` | Regenerates the README table from the registry (`--check` in CI). |
| `python3 scripts/registry.py package PLUGIN_DIR --out DIR` | Runs `build.sh`, writes the two release assets. |
| `python3 scripts/registry.py resolve --tag TAG` or `--path DIR` | Maps a release tag or plugin directory to its registry entry. |
| `python3 scripts/registry.py index [--assets-dir DIR] [--strict]` | Generates `community-index.json`; `--assets-dir` is a dry run using local assets instead of GitHub. |
| `python3 scripts/registry_smoke.py CLI PLUGIN_DIR` | Loads and renders the plugins with a released CLI. |
| `scripts/dry-run-release.sh PLUGIN_DIR CLI` | The whole release + index flow locally, without tagging or uploading. |
| `python3 -m unittest discover -s scripts` | Tests of the registry tooling (offline). |

## Not covered

* Only the latest version of each plugin is indexed (no version history or rollback list).
* A listing is not a security audit. The sandbox (no network or file access, memory and time
  limits) is the protection; see CONTRIBUTING.md.
* Release assets are not signed; integrity comes from the SHA-256 in the index plus HTTPS from
  github.com. Build provenance attestations could be added to `release-plugin.yml` later.
